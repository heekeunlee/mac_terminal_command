PM_BASICS

터미널이 처음이라면

터미널을 익히면 무엇이 달라질까

터미널은 개발자만의 도구가 아니다. 맥을 매일 쓰는 사람이라면 누구나, 몇 개의 단어만 익혀도 같은 컴퓨터를 전혀 다른 수준으로 다루게 된다.

1

반복을 한 줄로

사진 1,000장의 이름 바꾸기, 수백 개 파일 정리처럼 클릭으로 몇 시간 걸릴 일이 명령 한 줄로 끝난다. 한 번 쓴 명령은 저장해 두고 내일도 그대로 다시 쓴다.

2

보이지 않던 것이 보인다

숨김 파일, 폴더의 실제 용량, 지금 몰래 돌고 있는 프로그램. Finder가 감춰 둔 맥의 진짜 상태를 직접 확인할 수 있다.

3

막혔을 때 스스로 푼다

"디스크가 가득 찼다", "포트가 사용 중이다", "Permission denied". 원인을 추측하는 대신 명령으로 확인하고, 재부팅 없이 해결한다.

4

개발 도구의 공용어

Git, Node.js, Python, 클라우드 서버까지. 설치 안내서와 튜토리얼은 거의 모두 터미널 명령으로 쓰여 있다. 터미널을 알면 설명서를 그대로 따라 할 수 있다.

5

먼 컴퓨터도 내 것처럼

화면이 없는 서버, 멀리 있는 컴퓨터도 ssh 한 줄이면 내 맥처럼 다룬다. 웹사이트를 올리고 관리하는 일의 출발점이다.

6

한 번 배우면 오래 간다

50년 전에 태어난 ls, cp, mv가 지금도 똑같이 쓰인다. 앱 메뉴는 업데이트마다 바뀌지만 명령어는 거의 변하지 않고, 맥에서 익힌 명령은 리눅스 서버에서도 그대로 통한다.

이제 명령어를 외우기 전에, 처음 터미널을 연 사람이라면 누구나 한 번쯤 품는 질문부터 풀어본다.

터미널이 뭔가요?

평소 쓰는 macOS는 아이콘을 마우스로 눌러 프로그램을 실행하는 방식이다. 터미널(Terminal)은 그 대신 키보드로 글자 명령을 입력해서 컴퓨터에게 직접 지시하는 창이다. Finder가 그림으로 대화하는 창이라면 터미널은 글자로 대화하는 채팅창인 셈이다.

마우스가 있는데 왜 굳이 글자를 쳐야 하나요?

클릭은 한 번에 한 가지 일만 한다. 글자 명령은 반복하고, 조합하고, 저장할 수 있다. 사진 1,000장의 이름을 바꾸는 일은 마우스로는 1,000번의 클릭이지만 터미널에서는 한 줄이다. 한 번 쓴 명령은 파일로 저장해 내일도, 다른 컴퓨터에서도 똑같이 다시 실행할 수 있다. 개발자들이 검은 창을 떠나지 않는 이유다.

AI가 명령어를 알려 주는 시대에도 배워야 하나요?

오히려 더 필요하다. AI 챗봇과 코딩 도우미는 문제의 해결책을 터미널 명령으로 내놓는 경우가 많다. 그 명령이 무엇을 하는지 읽지 못하면 그대로 붙여넣는 수밖에 없다. rm -rf가 섞인 명령을 뜻도 모른 채 실행하는 것은 운전석에 앉아 눈을 감는 것과 같다. 명령을 읽을 줄 알면 AI의 제안을 검토하고, 고치고, 필요하면 거절할 수 있다. 이 책이 외우기보다 읽고 판단하는 힘을 목표로 하는 이유다.

터미널은 어떻게 여나요?

  1. 1Spotlight — Cmd + Space 누르고 "터미널" 입력 후 Enter
  2. 2Finder — 응용 프로그램 → 유틸리티 → 터미널
  3. 3Launchpad — Launchpad를 열고 "터미널" 검색

창에 보이는 글자들은 다 뭔가요?

터미널을 열면 가장 먼저 이런 한 줄이 기다리고 있다.

me@MacBook-Pro ~ %
  1. 1me로그인한 사용자 이름
  2. 2MacBook-Pro컴퓨터 이름
  3. 3~지금 있는 폴더 (홈)
  4. 4%입력을 기다리는 신호

이 한 줄 전체를 프롬프트(prompt)라 부른다. "무엇을 할까요?"라고 묻는 컴퓨터의 말이다. 그 뒤에 깜빡이는 네모가 커서, 지금 타이핑하면 글자가 나타날 자리다. 창 왼쪽 위 세 점은 macOS 공통 버튼으로 빨강은 닫기, 노랑은 최소화, 초록은 전체화면이다.

% 나 $ 같은 기호는 뭔가요?

%입력 대기 — zsh를 쓸 때 (macOS 기본, 2019년 이후)
$입력 대기 — bash·sh를 쓸 때 (이전 macOS, 리눅스 다수)
#입력 대기, 단 관리자(root) 권한으로 접속 중이라는 경고

기호가 다른 건 기능 차이가 아니라 어떤 셸을 쓰느냐의 전통 차이다. 인터넷에서 $ ls처럼 적힌 예시를 보면 맨 앞 기호는 빼고 뒤만 입력하면 된다. 다만 #은 예외다. 지금 무엇이든 바꿀 수 있는 관리자 권한이라는 뜻이니 한 글자 한 글자 조심해야 한다.

셸(shell), 그리고 zsh는 뭔가요?

셸은 입력한 명령을 알아듣고 macOS의 핵심부(커널)에 전달한 뒤 결과를 다시 보여주는 "통역사" 프로그램이다. 이름도 운영체제의 알맹이(커널)를 감싼 조개껍데기(shell)라는 비유에서 왔다.

zshZ Shell. macOS Catalina(2019)부터 기본 셸. 자동완성과 꾸미기 기능이 풍부함
bashBourne Again Shell. 2019년 이전 macOS와 대부분 리눅스의 기본 셸

내가 쓰는 셸이 궁금하면 echo $SHELL을 입력해보자. 이 책의 예시는 모두 zsh(%) 기준이다.

터미널과 셸은 같은 건가요?

다르다. 터미널은 창(화면과 키보드)이고, 셸은 그 안에서 말을 알아듣는 프로그램이다. 전화기와 통화 상대의 관계와 비슷하다. "터미널"은 원래 1970년대 거대한 컴퓨터에 전선으로 연결해 쓰던 키보드 달린 단말기(terminal) 기계의 이름이었다. 지금의 터미널 앱은 그 기계를 화면 속에 흉내 낸 것이다.

명령어는 왜 이렇게 짧고 암호 같나요?

유닉스가 태어난 1970년대에는 모니터 대신 종이에 글자를 찍어내는 텔레타이프로 컴퓨터를 썼다. 자판은 무겁고 출력은 느렸기 때문에 한 글자라도 줄이는 게 미덕이었다. 그래서 list는 ls, copy는 cp, move는 mv가 되었다. 50년 전 손가락의 수고가 오늘의 명령어 이름에 그대로 남아 있다.

~ 기호는 왜 "홈 폴더"라는 뜻이 됐나요?

1970년대 유닉스 개발자들이 즐겨 쓰던 ADM-3A라는 단말기에는 HOME 키와 ~ 기호가 같은 키에 새겨져 있었다. 이 우연 덕에 ~가 "집(홈)"을 가리키는 약속이 되었고, 지금도 cd ~는 언제든 내 홈 폴더로 돌아가는 명령이다.

잘못 입력하면 컴퓨터가 망가지나요?

대부분은 괜찮다. 오타를 내면 zsh: command not found라는 말만 돌아온다. 조심해야 할 것은 되돌릴 수 없는 명령(rm 같은 삭제)과, 관리자 권한으로 실행하는 sudo가 붙은 명령 정도다. 모르는 명령을 인터넷에서 복사해 붙여넣기 전에 한 번만 무슨 뜻인지 확인하는 습관이면 충분하다.

sudo는 뭐고, 비밀번호를 쳐도 왜 아무것도 안 보이나요?

sudo는 "superuser do", 이 명령 하나만 관리자 권한으로 실행해 달라는 뜻이다. 그래서 맥 로그인 비밀번호를 묻는다. 이때 글자가 전혀 안 보이는 건 고장이 아니라 옆 사람이 비밀번호의 길이조차 알 수 없게 하려는 설계다. 보이지 않아도 입력은 되고 있으니 그대로 치고 Enter를 누르면 된다.

명령이 멈추지 않아요. 어떻게 빠져나오나요?

Control + C를 누르면 실행 중인 명령을 중단한다. 긴 설명서 화면처럼 스크롤되는 곳에서는 q(quit)로 나온다. 이 둘만 알면 터미널에서 길을 잃을 일은 거의 없다.

매번 긴 명령을 다시 쳐야 하나요?

Tab파일·폴더 이름 앞 몇 글자만 치고 누르면 나머지를 자동완성
↑ / ↓이전에 입력한 명령을 다시 불러오기
Cmd + K화면 깨끗이 지우기 (clear 명령과 같음)
history지금까지 입력한 명령 목록 보기

모르는 명령어는 어디서 배우나요?

터미널 안에 설명서가 들어 있다. man ls처럼 man(manual) 뒤에 명령어를 적으면 그 명령의 공식 설명서가 열린다. 1971년 첫 유닉스 설명서부터 이어진 전통이다. 다 읽었으면 q로 나오면 된다.

이 책을 다 읽으면 무엇을 할 수 있나요?

예를 들어 이런 하루를 보낼 수 있다. 빈 폴더를 만들고, 막힌 포트를 뚫고, 완성한 사이트를 서버에 올리는 일까지 모두 터미널 몇 줄로 한다.

~ %mkdir -p ~/Projects/lecture-site && cd ~/Projects/lecture-site
lecture-site %kill $(lsof -t -i :5173)
lecture-site %grep -rn "TODO" src/
lecture-site %rsync -avz dist/ jimin@myserver:/var/www/lecture/
lecture-site %say -v Yuna "오늘 작업 끝"

이동과 둘러보기

터미널에서 길을 잃지 않는 세 가지 기본기. 지금 어디 있는지, 어디로 갈지, 무엇이 있는지.

PM_CMD_pwd

pwd

print working directory

이동

지금 내가 서 있는 폴더를 알려준다.

형식pwd
~ %pwd
/Users/me/Documents/lecture
유래

print working directory. "지금 작업 중인 폴더를 출력하라"는 뜻이다. 여기서 print가 프린터를 뜻하지 않는데도 굳이 print인 이유는, 텔레타이프 시절에는 결과가 정말로 종이에 인쇄되어 나왔기 때문이다.

주요 옵션
옵션원래 단어뜻
-PPhysical바로가기(링크)를 거쳐 들어왔다면, 바로가기 말고 실제 폴더의 위치를 보여준다.
-LLogical바로가기를 거쳐 온 경로를 그대로 보여준다. 아무것도 안 붙이면 이것.
상황별 예제

01길을 잃었을 때

pwd

프롬프트의 ~ 표시만으로 헷갈릴 때 전체 경로를 확인한다.

02경로를 복사해 두기

pwd | pbcopy

현재 경로가 클립보드에 들어간다. 메신저에 바로 붙여넣을 수 있다.

03링크 뒤의 진짜 위치

pwd -P

바로가기로 들어온 폴더라면 실제 폴더 경로가 나온다.

기억법

p-w-d를 "폴더 위치 답해"로 외워도 좋다. 원래 뜻은 print working directory.

꿀팁

Finder에서 폴더를 터미널 창에 끌어다 놓으면 그 폴더의 전체 경로가 자동으로 입력된다. pwd와 반대 방향의 요령이다.

PM_CMD_cd

cd

change directory

이동

다른 폴더로 이동한다.

형식cd [경로]
~ %cd Documents
프롬프트가 ~/Documents % 로 바뀜
~ %cd ..
한 단계 위 폴더로
유래

change directory. 초기 유닉스 셸에서는 chdir이라는 조금 더 긴 이름이었다가, 가장 자주 치는 명령답게 두 글자 cd로 줄었다.

특별한 경로 기호
옵션원래 단어뜻
~tilde = home내 홈 폴더(/Users/내이름). cd ~는 "집으로 돌아가기".
..parent지금 폴더를 담고 있는 한 단계 위 폴더.
-previous바로 전에 있던 폴더. 두 폴더를 오갈 때 편하다.

상황별 예제

01어디서든 집으로

cd

아무것도 안 붙이면 홈 폴더로 돌아간다. cd ~와 같다.

02두 폴더를 왔다 갔다

cd -

직전 폴더로 돌아간다. 한 번 더 치면 다시 원래 자리로.

03이름에 공백이 있을 때

cd "My Projects"

04두 단계 위로

05Tab으로 빠르게

비하인드 스토리

PM_CMD_touch

touch

touch (살짝 건드리다)

파일·디렉토리

형식touch 파일명

옵션원래 단어뜻

비하인드 스토리

빌드 도구 make는 파일의 수정 시각을 보고 다시 컴파일할지 결정한다. 그래서 개발자들은 내용은 그대로 두고 touch로 파일을 "건드려" 강제로 다시 빌드시키곤 했다. 이름이 기능을 그대로 설명하는 드문 명령어다.

PM_CMD_rm

rm

remove

파일·디렉토리

파일과 폴더를 휴지통 없이 지운다.

형식rm [옵션] 파일명
~ %rm draft.txt
(휴지통을 거치지 않고 즉시 삭제)
~ %rm -r old_project/
폴더와 내용물 전부 삭제
주요 옵션
옵션원래 단어뜻
-rrecursive폴더와 그 안의 파일·하위 폴더까지 전부 지운다. 폴더를 지울 때 필요하다.
-fforce"정말 지울까요?"를 묻지 않는다. 없는 파일이어도 오류 없이 넘어간다.
-iinteractive파일마다 "지울까요?"라고 묻고, y를 눌러야 지운다.

유래

remove를 그대로 줄인 이름. Finder의 휴지통과 달리 완전히 즉시 삭제되며, 복구 경로가 사실상 없다는 점이 가장 중요한 특징이다.

상황별 예제

01여러 파일 한꺼번에

파일마다 remove? 라고 묻고, y를 눌러야 지운다.

PM_CMD_cp

cp

copy

파일·디렉토리

복사본을 만든다. 원본은 그대로.

형식cp 원본 대상
~ %cp report.txt backup.txt
report.txt는 그대로 있고 backup.txt가 새로 생김

옵션원래 단어뜻
-RRecursive폴더를 안의 내용까지 통째로 복사한다. 폴더를 복사할 때 필수다. 소문자 -r도 같다.
-iinteractive같은 이름의 파일이 이미 있으면 덮어쓸지 먼저 묻는다.
-nno-clobber같은 이름의 파일이 이미 있으면 복사하지 않고 그대로 둔다.
-vverbose복사한 파일 이름을 하나씩 보여준다.

유래

copy를 그대로 줄인 이름. 이름에 특별한 사연은 없지만, mv와 짝을 이루는 가장 기본적인 파일 조작 명령이다.

less

PM_CMD_find

find

find

검색

조건에 맞는 파일을 찾아낸다.

형식find 검색경로 -조건 값
~ %find . -name "*.txt"
./notes/report.txt
./draft.txt
~ %find . -mtime -7
최근 7일 이내 수정된 파일만 표시
주요 옵션
옵션원래 단어뜻
-namename파일 이름으로 찾는다. *는 '아무 글자나'라는 뜻이다. 예: "*.txt". 대소문자를 구분한다.
-inameinsensitive name-name과 같지만 대소문자를 가리지 않는다. Photo.JPG와 photo.jpg를 모두 찾는다.
-typetype (f=file, d=directory)f를 붙이면 파일만, d를 붙이면 폴더만 찾는다.
-sizesize크기로 찾는다. +500M은 500MB보다 큰 것, -1k는 1KB보다 작은 것.
-mtimemodification time고친 날짜로 찾는다. -7은 7일 이내, +30은 30일보다 오래된 것.
-execexecute찾은 파일마다 뒤에 적은 명령을 실행한다. {}는 찾은 파일, \;는 명령의 끝.
삭제와 조합

find . -name "*.log" -delete 처럼 삭제와 묶어 쓸 수 있다. 되돌릴 수 없으니 -delete를 빼고 먼저 실행해 어떤 파일이 걸리는지 확인한 뒤 붙이는 게 안전하다.

PM_CMD_chmod

chmod

change mode

권한

누가 읽고 쓰고 실행할지 정한다.

형식chmod 숫자|기호 파일명
~ %chmod +x deploy.sh
실행 권한 추가, ./deploy.sh 로 실행 가능
~ %chmod 755 deploy.sh
소유자 rwx, 그룹·기타 r-x
권한 숫자표
7rwx · 열어 보고, 고치고, 실행까지 모두 할 수 있다. (4+2+1)
6rw- · 열어 보고 고칠 수 있지만 실행은 못 한다. (4+2)
5r-x · 열어 보고 실행할 수 있지만 고치지는 못 한다. (4+1)
4r-- · 열어 보기만 할 수 있다. (4)
0--- · 아무것도 할 수 없다.
기호의 뜻
옵션원래 단어뜻
u / g / o / auser · group · others · all권한을 바꿀 대상. u는 파일 주인, g는 같은 그룹 사람들, o는 그 밖의 모든 사람, a는 셋 모두.
r / w / xread · write · execute바꿀 권한. r은 읽기(열어 보기), w는 쓰기(고치기), x는 실행(프로그램처럼 돌리기).
+ / - / =add · remove · set+는 권한을 더하고, -는 빼고, =는 정확히 그것만 남긴다. 예: u+x, g-w, o=r
-RRecursive폴더 안의 모든 파일과 하위 폴더에 같은 권한을 한꺼번에 적용한다.
상황별 예제

이제 ./build.sh 로 바로 실행할 수 있다.

키가 남에게 열려 있으면 ssh가 사용을 거부한다. 600은 나만 읽고 쓰기.

chmod -R 755 public/

나는 모든 권한, 나머지는 읽기와 실행만.

04그룹의 쓰기 권한만 빼기

chmod g-w shared.txt

그룹(g)에서 쓰기(w)를 뺀다(-). 나머지는 그대로.

05바뀌었는지 확인

-rwxr-xr-x 처럼 x가 보이면 실행 권한이 생긴 것이다.

기억법

r=4, w=2, x=1은 2진수 자리값(100, 010, 001)과 같다. 원하는 권한을 더하면 그게 곧 숫자다: 읽기+실행만 원하면 4+1=5.

꿀팁

chmod 777(모두에게 모든 권한)은 편하지만 보안 위험이 크다. 꼭 필요한 최소 권한만 주는 습관을 들이자.

chown

권한

파일의 주인을 바꾼다.

형식chown 사용자[:그룹] 파일명

~ %ls -l data.txt

유래

주요 옵션
옵션원래 단어뜻
-RRecursive폴더 안의 모든 파일과 하위 폴더의 주인을 한꺼번에 바꾼다.
-vverbose주인이 바뀐 파일 이름을 보여준다.
-hsymlink (관례상 h)바로가기가 가리키는 원본 말고, 바로가기 파일 자체의 주인을 바꾼다.
상황별 예제

01root 것이 된 파일 되찾기

sudo chown $(whoami) report.txt

$(whoami)는 내 사용자 이름으로 바뀐다.

02npm 권한 오류 해결

sudo chown -R $(whoami) ~/.npm

sudo npm으로 설치하다 꼬인 캐시 폴더의 주인을 나로 되돌린다.

03그룹까지 함께

sudo chown me:staff shared.txt

콜론(:) 뒤가 그룹이다.

기억법

chmod는 mode(권한), chown은 owner(주인). 둘 다 change로 시작하는 형제 명령이다.

꿀팁

sudo로 만든 파일은 주인이 root가 되어 나중에 평범하게 수정할 수 없다. "Permission denied"가 뜨면 ls -l로 주인부터 확인하자.

PM_CMD_sudo

sudo

superuser do

권한

이 명령 하나만 관리자 권한으로 실행한다.

형식sudo 명령어
~ %sudo softwareupdate -l
Password:
맥 로그인 비밀번호 입력 (화면에 안 보이는 게 정상)
유래

superuser do, "관리자로서 실행하라". 1980년 뉴욕주립대 버펄로에서 처음 만들어졌다. 관리자 계정으로 아예 로그인하지 않고 필요한 순간에만 권한을 빌리게 해 사고를 줄이는 것이 목적이다.

주요 옵션
옵션원래 단어뜻
-iinteractive login명령 하나가 아니라 아예 관리자 상태로 들어간다. 프롬프트가 #으로 바뀌고, exit로 나온다.
-kkill timestamp비밀번호 기억을 지워, 다음 sudo 때 다시 묻게 한다.
-uuser관리자 대신 지정한 다른 사용자로 실행한다.
상황별 예제

01방금 명령을 관리자로 다시

sudo !!

!!는 직전 명령. Permission denied가 떴을 때 처음부터 다시 칠 필요가 없다.

02시스템 파일 수정

sudo nano /etc/hosts

특정 사이트 주소를 직접 지정할 때 쓰는 파일이다.

03DNS 캐시 비우기 (macOS)

sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder

사이트 주소가 바뀌었는데 예전 곳으로 접속될 때 쓴다.

04권한 빌린 상태 끝내기

sudo -k

잠시 동안 비밀번호를 다시 묻지 않는 상태를 바로 끝낸다.

비하인드 스토리

유명한 웹툰 xkcd에는 "샌드위치 만들어 줘"라는 말에 "네가 만들어"라고 거절당하던 사람이 "sudo 샌드위치 만들어 줘"라고 하자 "알겠어"라는 답을 듣는 장면이 있다. 이후 sudo는 개발자들 사이에서 "꼭 좀"이라는 뜻의 농담으로도 쓰인다.

꿀팁

인터넷에서 복사한 sudo 명령은 컴퓨터 전체를 바꿀 수 있다. 붙여넣기 전에 무슨 뜻인지 반드시 확인하자.

압축과 보관

여러 파일을 하나로 묶거나 다시 푸는 두 가지 방법. 맥·리눅스끼리는 tar, 윈도우와는 zip.

PM_CMD_tar

tar

tape archive

압축

여러 파일을 하나로 묶고 푼다.

형식tar 옵션 파일명.tar.gz 대상
~ %tar -czvf backup.tar.gz src/
src 폴더를 backup.tar.gz 하나로 압축
~ %tar -xzvf backup.tar.gz
현재 위치에 압축 풀기
주요 옵션
옵션원래 단어뜻
-ccreate새 압축 파일을 만든다.
-xextract압축 파일을 풀어 원래 파일들로 꺼낸다.
-ttable of contents풀지 않고 안에 든 파일 목록만 보여준다.
-zgzipgzip 방식으로 압축하거나 푼다. 이름이 .tar.gz인 파일을 다룰 때 필요하다.
-vverbose처리 중인 파일 이름을 하나씩 보여준다.
-ffile바로 뒤에 압축 파일 이름이 온다는 표시. 그래서 항상 옵션의 맨 끝에 둔다.
-CChange directory압축을 풀 폴더를 지정한다. 없으면 지금 있는 폴더에 풀린다.
유래

tape + archive. 1970년대에 여러 파일을 자기 테이프(tape)에 순서대로 이어 기록해 보관(archive)하던 방식에서 이름이 그대로 남았다. 여러 파일이 하나로 뭉쳐진 결과물을 "타볼(tarball)"이라 부르는 것도 여기서 나온 은어다.

상황별 예제

01풀기 전에 안을 들여다보기

tar -tzvf backup.tar.gz

압축을 풀지 않고 들어 있는 파일 목록만 본다.

02원하는 폴더에 풀기

tar -xzvf backup.tar.gz -C ~/restore

-C로 지정한 폴더 안에 풀린다. 폴더는 미리 있어야 한다.

03여러 대상을 하나로

tar -czvf site.tar.gz index.html css/ js/

파일과 폴더를 섞어 한 파일로 묶는다.

04무거운 폴더는 빼고

tar -czvf project.tar.gz --exclude=node_modules project/

다시 받을 수 있는 node_modules는 제외해 용량을 줄인다.

05날짜가 붙은 백업 파일

tar -czf docs-$(date +%Y%m%d).tar.gz docs/

docs-20260930.tar.gz 처럼 날짜가 이름에 들어간다.

꿀팁

압축을 풀지 않고 안에 뭐가 들었는지만 보고 싶다면 tar -tzvf 파일명 을 쓰면 된다.

PM_CMD_zip

zip

zip (지퍼) · unzip

압축

윈도우와도 호환되는 zip 파일로 묶고 푼다.

형식zip -r 이름.zip 대상 / unzip 이름.zip
~ %zip -r photos.zip photos/
adding: photos/a.jpg (deflated 3%)
~ %unzip photos.zip -d restore/
restore 폴더에 압축 해제
유래

지퍼(zip)처럼 빠르게 잠근다는 뜻. 1989년 필 카츠가 만든 PKZIP에서 시작된 형식으로, 지금은 운영체제를 가리지 않는 가장 흔한 압축 형식이 되었다.

주요 옵션
옵션원래 단어뜻
-rrecursive폴더를 안의 내용까지 통째로 압축한다. 폴더를 압축할 때 필수다.
-eencrypt압축 파일에 비밀번호를 건다. 확인을 위해 두 번 입력한다.
-xexclude압축에서 뺄 파일을 지정한다. 예: -x "*.DS_Store"
-qquiet압축하는 파일 목록을 화면에 보여주지 않는다.
unzip -llist풀지 않고 안에 든 파일 목록만 보여준다.
unzip -ddirectory압축을 풀 폴더를 지정한다.
상황별 예제

01비밀번호 걸어 보내기

zip -er secret.zip contracts/

두 번 입력한 비밀번호가 있어야 열 수 있다.

02맥 찌꺼기 빼고 압축

zip -r site.zip site -x "*.DS_Store"

윈도우 사용자에게 보낼 때 깔끔하다.

03열기 전에 내용 확인

unzip -l archive.zip

어떤 파일이 들었는지 목록만 본다.

꿀팁

Finder의 "압축하기"로 만든 zip에는 __MACOSX라는 숨은 폴더가 섞여 윈도우 사용자가 당황하곤 한다. 터미널의 zip을 쓰면 이 문제가 없다.

기억법

맥·리눅스끼리는 tar.gz, 윈도우 사용자에게 보낼 때는 zip. 받는 사람을 먼저 생각하면 고르기 쉽다.

네트워크와 원격 접속

연결을 확인하고, 인터넷에서 데이터를 가져오고, 다른 컴퓨터에 안전하게 접속해 파일을 주고받는다.

PM_CMD_ping

ping

ping (소나의 핑 소리)

네트워크

상대 컴퓨터에 신호를 보내 응답을 확인한다.

형식ping 주소
~ %ping -c 3 google.com
64 bytes from 142.250.206.46: icmp_seq=0 ttl=117 time=31.2 ms
3 packets transmitted, 3 packets received, 0.0% packet loss
유래

잠수함 소나가 음파를 쏘고 되돌아오는 "핑" 소리에서 이름을 땄다. 1983년 마이크 무스가 하룻밤 사이에 만들었다. 흔히 Packet InterNet Groper의 약자로 소개되지만, 이는 나중에 끼워 맞춘 풀이다.

주요 옵션
옵션원래 단어뜻
-ccount신호를 몇 번 보낼지 정한다. 없으면 Control+C를 누를 때까지 계속 보낸다.
-iinterval신호를 보내는 간격(초)을 정한다. 기본은 1초.
-ttimeout몇 초가 지나면 자동으로 멈출지 정한다.
상황별 예제

01인터넷이 되나

ping -c 3 8.8.8.8

응답이 오면 인터넷 연결 자체는 살아 있다.

02인터넷 문제인가 주소 문제인가

ping -c 3 google.com

8.8.8.8은 되는데 이게 안 되면 주소를 찾아주는 DNS 문제다.

03공유기까지는 되나

ping 192.168.0.1

집 안 연결부터 점검한다. Control+C로 멈추면 통계가 나온다.

비하인드 스토리

time=31.2 ms는 신호가 갔다가 돌아오는 데 걸린 시간이다. 게이머들이 말하는 "핑이 튄다"의 핑이 바로 이 숫자다.

PM_CMD_curl

curl

client URL

네트워크

인터넷 주소와 데이터를 주고받는다.

형식curl [옵션] URL
~ %curl -O https://example.com/file.zip
원본 파일명 그대로 다운로드
~ %curl -I https://example.com
HTTP/2 200
content-type: text/html
주요 옵션
옵션원래 단어뜻
-ooutput받은 내용을 내가 정한 이름의 파일로 저장한다. 예: -o logo.png
-Oremote-name Output받은 파일을 서버에 있던 이름 그대로 저장한다.
-LLocation주소가 다른 곳으로 옮겨졌으면 따라가서 받는다. 없으면 빈 파일을 받기도 한다.
-Ihead (Info)내용은 빼고, 서버의 응답 정보(상태 번호, 파일 형식 등)만 본다.
-ssilent진행률 같은 표시를 숨기고 결과만 보여준다.
-Xrequest (관례상 X)요청 방식을 정한다. 가져오기는 GET(기본값), 보내기는 POST.
-HHeader요청에 추가 정보를 붙인다. 예: 데이터 형식, 인증 키.
-ddata서버로 보낼 데이터를 적는다. 쓰면 자동으로 POST 방식이 된다.
유래

"Client URL"의 줄임말. 1996년 스웨덴 개발자 다니엘 스텐베리가 만든 httpget이 urlget을 거쳐 curl로 이름을 바꿨다.

상황별 예제

01이름을 바꿔 저장

curl -o logo.png https://example.com/image.png

소문자 o 뒤에 원하는 파일 이름을 적는다.

02리다이렉트되는 링크 받기

curl -LO https://example.com/latest.zip

GitHub 릴리스처럼 주소가 한 번 옮겨지는 링크는 -L이 필요하다.

03터미널에서 날씨 보기

curl wttr.in/Seoul

서울 날씨가 글자 그림으로 나온다. curl로 할 수 있는 가벼운 장난.

04사이트가 살아 있나

curl -s -o /dev/null -w "%{http_code}" https://example.com

200이면 정상, 404는 없음, 500번대는 서버 오류다.

05API에 데이터 보내기

curl -X POST -H "Content-Type: application/json" -d '{"name":"kim"}' https://api.example.com/users

JSON 데이터를 POST 방식으로 서버에 보낸다.

꿀팁

API 키 같은 민감정보를 -H나 -d에 직접 적으면 터미널 히스토리에 평문으로 남는다. 환경변수나 별도 설정 파일로 분리하는 편이 안전하다.

PM_CMD_wget

wget

web get

네트워크

인터넷에서 파일을 내려받는다.

형식wget URL
~ %wget https://example.com/file.zip
현재 위치에 file.zip으로 자동 저장
주요 옵션
옵션원래 단어뜻
-OOutput document저장할 파일 이름을 직접 정한다.
-ccontinue다운로드가 끊겼을 때 처음부터가 아니라 받던 곳부터 이어 받는다.
-iinput file주소가 한 줄에 하나씩 적힌 파일을 주면, 목록의 파일을 차례로 모두 받는다.
-rrecursive페이지 안의 링크를 따라가며 연결된 파일까지 받는다.
curl과 무엇이 다른가
wget다운로드 특화, 재귀 다운로드(-r) 지원, 이어받기 강함
curlAPI 호출 특화, 헤더·메소드 세밀 제어
유래

web + get. GNU 프로젝트로 1996년 등장했고, 원래 후보 이름은 "geturl"이었지만 상표 문제로 wget이 되었다. macOS엔 기본 내장돼 있지 않아 보통 brew install wget으로 따로 설치한다.

상황별 예제

01설치부터

brew install wget

macOS에는 기본으로 없으니 Homebrew로 설치한다.

02끊긴 다운로드 이어받기

wget -c https://example.com/big.iso

받던 곳부터 이어서 받는다. 큰 파일에 유용하다.

03이름을 정해서 저장

wget -O data.csv https://example.com/export

대문자 O 뒤에 저장할 이름을 적는다.

04목록에 있는 파일 전부

wget -i urls.txt

한 줄에 하나씩 적힌 주소를 차례로 모두 받는다.

PM_CMD_ssh

ssh

secure shell

네트워크

다른 컴퓨터에 안전하게 접속한다.

형식ssh 사용자명@호스트주소
~ %ssh user@example.com
비밀번호 또는 키 인증 후 원격 셸 접속
~ %ssh -i ~/.ssh/id_ed25519 user@example.com
지정한 키 파일로 접속
주요 옵션
옵션원래 단어뜻
-pport접속할 포트(문) 번호를 정한다. 적지 않으면 22번.
-iidentity file비밀번호 대신 쓸 개인 키 파일을 지정한다.

-LLocal forward서버의 특정 포트를 내 맥의 포트로 이어준다. 예: 서버의 데이터베이스를 내 맥에서 열기.
자주 같이 쓰는 도구

상황별 예제

01포트가 다른 서버

ssh -p 2222 user@example.com

관리자가 기본 22번 대신 다른 포트를 열어둔 경우다.

02접속하지 않고 명령만

ssh user@example.com "df -h"

서버의 디스크 상태만 받아오고 바로 연결을 끝낸다.

03내 키 만들기

ssh-keygen -t ed25519 -C "me@example.com"

~/.ssh/에 개인키와 공개키(.pub)가 생긴다.

04비밀번호 없이 접속하게

ssh-copy-id user@example.com

내 공개키를 서버에 등록한다. 다음부터는 키로 자동 인증된다.

05접속 끝내기

exit

원래 내 맥의 터미널로 돌아온다. Control+D도 같다.

비하인드 스토리

1995년 핀란드 헬싱키공과대학의 타투 윌로넨은 자신이 속한 대학 네트워크에서 비밀번호를 가로채는 스니핑 공격을 직접 당했다. 당시 널리 쓰이던 rlogin과 telnet은 비밀번호를 암호화 없이 그대로 전송하고 있었기 때문. 이 경험이 계기가 되어 그는 암호화된 원격 접속 프로그램 ssh를 직접 만들었고, 오늘날까지 원격 접속의 표준이 되었다.

PM_CMD_scp

scp

secure copy

네트워크

다른 컴퓨터와 파일을 주고받는다.

형식scp 원본 대상
~ %scp file.txt user@example.com:~/backup/
로컬 → 원격 업로드
~ %scp -r src/ user@example.com:~/app/
폴더 전체 복사(재귀)
주요 옵션
옵션원래 단어뜻
-rrecursive폴더를 안의 내용까지 통째로 복사한다.
-PPort포트 번호를 정한다. ssh와 달리 대문자 P다. 소문자 -p는 다른 뜻.
-ppreserve원본의 수정 날짜와 권한을 그대로 유지한다.
-iidentity file비밀번호 대신 쓸 개인 키 파일을 지정한다.
유래

secure copy. ssh 위에서 동작하며, 비밀번호를 암호화 없이 주고받던 예전의 rcp(remote copy)를 대체하기 위해 등장했다.

01서버 파일을 내 맥으로

콜론(:) 뒤가 서버 쪽 경로, ./는 지금 폴더다.

02사진 여러 장 올리기

03포트가 다를 때

scp -P 2222 file.txt user@example.com:~/

ssh와 달리 대문자 P다.

04별칭으로 짧게

scp file.txt myserver:~/

꿀팁

ssh는 소문자 -p, scp는 대문자 -P로 포트를 지정한다. 실무에서 가장 자주 헷갈리는 옵션 중 하나다.

옵션원래 단어뜻

무엇이 복사되고 지워질지 목록만 보여준다. 확인 후 n을 뺀다.

비하인드 스토리

1996년 호주 개발자 앤드루 트리젤(삼바 SMB 서버 개발자로도 유명하다)은 박사 논문에서 "두 파일의 차이 나는 조각만 찾아 전송하는" 알고리즘을 제안했다. 이 알고리즘을 그대로 구현한 것이 rsync이며, 지금도 백업 도구 대부분이 이 방식을 빌려 쓰고 있다.

PM_CMD_top

top

top (맨 위)

프로세스

자원을 가장 많이 쓰는 프로그램을 실시간으로 보여준다.

형식top [-o 정렬기준]
~ %top -o cpu
PID COMMAND %CPU MEM
4821 node 87.3 412M
612 WindowServer 12.1 256M
계속 갱신, q로 종료
유래

자원을 가장 많이 쓰는, 순위의 맨 위(top) 프로그램들을 보여준다는 뜻. 1984년 윌리엄 르페브르가 만들었다. macOS의 활동 모니터 앱과 같은 정보를 터미널에서 본다.

주요 옵션
옵션원래 단어뜻
-oorder무엇을 기준으로 줄 세울지 정한다. cpu는 CPU 사용량, mem은 메모리 사용량.
-nnumber화면에 보여줄 프로그램 개수를 정한다.
-llogging samples계속 갱신하지 않고, 정한 횟수만큼만 결과를 찍고 끝낸다. (macOS)
qquittop 화면을 닫고 터미널로 돌아온다.

PM_CMD_kill

kill

신호(signal)를 보내는 명령

프로세스

프로그램에 신호를 보내 멈추게 한다.

형식kill [-신호번호] PID
~ %kill 12345
정상 종료 신호(SIGTERM) 전송, 프로세스가 정리 후 종료

강제 종료(SIGKILL), 즉시 종료
신호와 옵션
옵션원래 단어뜻
-15SIGTERM · terminate프로그램에게 "정리하고 끝내 주세요"라고 부탁한다. 숫자를 안 쓰면 이것이다.

PM_CMD_lsof

lsof

list open files

프로세스

어떤 프로그램이 무엇을 붙잡고 있는지 보여준다.

형식lsof [옵션]
~ %lsof -i :3000
COMMAND PID USER FD TYPE NAME
node 4821 me 23u IPv6 *:3000 (LISTEN)
유래

list open files, 열려 있는 파일 목록. 유닉스에는 "모든 것은 파일이다"라는 철학이 있어서 네트워크 연결까지 파일처럼 다룬다. 그래서 파일 목록 명령으로 포트까지 찾을 수 있다.

주요 옵션
옵션원래 단어뜻
-iinternet네트워크 연결만 본다. -i :3000처럼 포트 번호를 붙일 수 있다.
-tterse다른 정보 없이 프로그램 번호(PID)만 보여준다. kill과 함께 쓰기 좋다.
-pprocess지정한 번호(PID)의 프로그램이 열고 있는 파일을 보여준다.
+DDirectory지정한 폴더 안에서 열려 있는 파일을 모두 찾는다.

PM_CMD_source

source

셸 설정

설정 파일을 지금 창에 바로 적용한다.

형식source 파일명

터미널을 새로 열지 않고도 방금 수정한 설정을 즉시 반영

3해결

찾은 파일들에만 한꺼번에 바꾸기를 적용한다

grep이 찾은 파일 목록을 xargs로 sed에 넘긴다. 원본은 .bak 파일로 남겨 두어 문제가 생기면 되돌릴 수 있게 한다.

~ %grep -rl "쿠버네티즈" docs/ | xargs sed -i .bak 's/쿠버네티즈/쿠버네티스/g'

grep -rl … docs/오타가 있는 파일 이름 목록을 만든다

sed글자를 바꾸는 명령 (stream editor)
-i .bak원본 파일을 직접 고치되, 고치기 전 내용을 같은 이름.bak으로 남긴다
