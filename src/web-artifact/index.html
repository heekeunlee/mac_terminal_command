맥 터미널 명령어 사전

처음 터미널을 여는 사람도, 자주 쓰지만 헷갈리는 사람도 함께 보는 참고서. 명령어마다 쓰는 형식과 실제 예시, 이름의 유래와 약자, 외우는 요령과 실무 꿀팁, 그리고 알아두면 재미있는 뒷이야기까지 한 자리에 정리했다.

명령어 23개 분류 8개 기본 셸 zsh (%) 기준
~ %mkdir lecture_notes
~ %cd lecture_notes
~/lecture_notes %ls -la
drwxr-xr-x 2 me staff 64 9 29 09:12 .
drwxr-xr-x 9 me staff 288 9 29 09:12 ..

터미널이 처음이라면

본격적으로 명령어를 익히기 전에, 터미널이 정확히 뭐고 화면에 보이는 것들이 각각 무슨 뜻인지부터 짚고 넘어간다.

터미널이 뭔가요?

평소 쓰는 macOS는 아이콘을 마우스로 눌러 프로그램을 실행하는 방식이다. 터미널(Terminal)은 그 대신 키보드로 글자 명령을 입력해서 컴퓨터에게 직접 지시하는 창이다. Finder가 그림으로 대화하는 창이라면 터미널은 글자로 대화하는 채팅창인 셈이다. macOS에는 "터미널"이라는 이름의 앱이 기본으로 들어 있다.

실행하는 방법

  1. 1Spotlight 이용 — Cmd + Space를 누른 뒤 "터미널"이라 입력하고 Enter
  2. 2Finder에서 찾기 — Finder → 응용 프로그램 → 유틸리티 → 터미널
  3. 3Launchpad에서 찾기 — Launchpad를 열고 "터미널" 검색

화면 구성 뜯어보기

me@MacBook-Pro ~ % ls
Desktop Documents Downloads
me@MacBook-Pro ~ % ▍

창 맨 위 세 개의 점은 macOS 공통 창 조절 버튼이다 — 빨강은 닫기, 노랑은 최소화(Dock으로), 초록은 전체화면.

me사용자 계정명
@
MacBook-Pro컴퓨터 이름
~현재 위치
(~는 홈 폴더)
%명령 대기 신호

이 전체를 프롬프트(prompt)라 부른다. "이제 명령을 입력할 준비가 됐다"는 뜻이다. 프롬프트 뒤 깜빡이는 막대(▍)가 커서로, 지금 타이핑하면 이 자리에 글자가 나타난다.

% 나 $ 같은 기호는 뭔가요?

%명령 입력 대기 — zsh를 쓸 때 (macOS 기본, 2019년 이후)
$명령 입력 대기 — bash·sh를 쓸 때 (이전 macOS, 리눅스 다수)
#명령 입력 대기, 단 관리자(root) 권한으로 접속 중이라는 경고

기호가 다른 건 기능 차이가 아니라 어떤 셸(shell)을 쓰느냐의 전통 차이다. 다만 #만은 예외 — 지금 뭐든 마음대로 바꿀 수 있는 관리자 권한이라는 뜻이니 더 조심해야 한다.

셸(shell), 그리고 zsh는 뭔가요?

셸(shell)은 입력한 명령을 이해해서 macOS의 핵심 부분(커널)에 전달하고, 그 결과를 다시 화면에 보여주는 "통역사" 프로그램이다. 이름 자체도 운영체제의 알맹이(커널)를 감싸는 조개껍데기(shell)라는 비유에서 왔다.

zshZ Shell. macOS Catalina(2019)부터 애플의 기본 셸. 자동완성과 커스터마이징 기능이 풍부해 개발자들이 즐겨 씀
bashBourne Again Shell. 2019년 이전 macOS 기본 셸이자 지금도 리눅스 대부분의 기본 셸

지금 어떤 셸을 쓰고 있는지 궁금하면 터미널에 echo $SHELL을 입력해보면 된다. 이 책의 모든 예시는 macOS 기본값인 zsh(% 기호) 기준으로 작성했다.

01

파일과 디렉토리 다루기

폴더를 만들고 지우고, 파일을 복사·이동하고, 안의 내용을 들여다보는 가장 기본적인 6개 명령어.

mkdir

make directory

파일·디렉토리
형식mkdir [옵션] 디렉토리명
~ %mkdir photos
(출력 없음 — 성공하면 아무 말도 하지 않는 것이 유닉스 방식)
~ %mkdir -p 2026/09/lecture
2026, 2026/09 폴더가 없어도 한 번에 전부 생성됨
유래

1970년대 초기 유닉스부터 있던 명령어. 그 시절 디렉토리는 특수한 형태의 파일이라 mknod 같은 저수준 명령으로도 만들 수 있었지만, 실수 위험이 커서 안전하게 디렉토리만 만드는 전용 명령으로 따로 뗐다.

주요 옵션
-pparents, 상위 경로가 없어도 한 번에 생성
-m생성과 동시에 권한(mode) 지정
기억법

make + directory를 줄이면 그대로 mkdir. "메이크 디렉토리"를 빠르게 이어 읽으면 명령어 이름이 된다.

꿀팁

-p 없이 mkdir a/b를 실행했는데 a가 없으면 에러가 난다. 중첩 폴더를 만들 땐 습관적으로 -p를 붙이면 안전하다.

↑ 목차로

rmdir

remove directory

파일·디렉토리
형식rmdir 디렉토리명
~ %rmdir empty_folder
(비어 있으면 조용히 삭제)
~ %rmdir photos
rmdir: photos: Directory not empty
유래

remove + directory. mkdir의 반대 짝. 오직 "완전히 빈 폴더"만 지울 수 있도록 설계해, 실수로 내용물 가득한 폴더를 날리는 사고를 원천적으로 막는다.

rm -r 과의 차이
rmdir빈 폴더만 삭제 가능, 안전
rm -r내용물 포함 통째로 삭제, 위험
기억법

rm(지우기) + dir(디렉토리). "빈 방만 치울 수 있다"로 기억하면 rm -r과 헷갈리지 않는다.

비하인드 스토리

rm -r 하나로 통합할 수도 있었지만 유닉스 설계자들은 굳이 rmdir을 따로 남겨뒀다. "위험한 동작일수록 명시적으로 요청해야 한다"는 초기 유닉스의 설계 철학이 명령어 하나에도 그대로 스며 있다.

↑ 목차로

rm

remove

파일·디렉토리
형식rm [옵션] 파일명
~ %rm draft.txt
(휴지통을 거치지 않고 즉시 삭제)
~ %rm -r old_project/
폴더와 내용물 전부 삭제
주요 옵션
-rrecursive, 폴더 내용까지 재귀적으로 삭제
-fforce, 확인 없이 강제 삭제
-iinteractive, 삭제 전 하나하나 확인
유래

remove를 그대로 줄인 이름. Finder의 휴지통과 달리 완전히 즉시 삭제되며, 복구 경로가 사실상 없다는 점이 가장 중요한 특징이다.

꿀팁

삭제 대상이 넓은 명령(rm -rf 폴더/*)을 실행하기 전엔 같은 경로로 ls를 먼저 실행해 무엇이 지워질지 눈으로 확인하는 습관이 사고를 막아준다.

비하인드 스토리

2015년 스팀(Steam) 리눅스 클라이언트에는 rm -rf "$STEAMROOT/"* 라는 코드가 있었는데, 특정 조건에서 STEAMROOT 변수가 빈 값이 되면서 사실상 rm -rf /* 처럼 동작해 사용자 홈 폴더 전체를 삭제해버린 사건이 있었다. 변수 하나, 따옴표 하나가 시스템 전체를 위협할 수 있다는 것을 보여준 유명한 사고로 지금도 개발자들 사이에서 경고 사례로 회자된다.

↑ 목차로

cp

copy

파일·디렉토리
형식cp 원본 대상
~ %cp report.txt backup.txt
report.txt는 그대로 있고 backup.txt가 새로 생김
~ %cp -r project/ project_backup/
폴더 전체가 복사됨
주요 옵션
-r폴더 복사 시 필수(재귀적으로 복사)
-i덮어쓰기 전 확인
-v복사 과정 출력
-p권한·타임스탬프 유지
유래

copy를 그대로 줄인 이름. 이름에 특별한 사연은 없지만, mv와 짝을 이루는 가장 기본적인 파일 조작 명령이다.

기억법

cp는 원본과 사본, 둘 다 남는다. mv는 하나만 남는다 — 이 대비로 두 명령을 함께 외우면 절대 안 헷갈린다.

꿀팁

대상 파일이 이미 있으면 확인 없이 바로 덮어쓴다. 중요한 파일을 다룰 땐 cp -i 습관을 들이자.

↑ 목차로

mv

move

파일·디렉토리
형식mv 원본 대상
~ %mv old.txt new.txt
이름만 바뀜(같은 위치)
~ %mv report.txt ~/Desktop/
Desktop 폴더로 이동, 원본 위치엔 남지 않음
유래

move를 그대로 줄인 이름. cp와 달리 폴더 이동에도 -r 옵션이 필요 없다.

주요 옵션
-i덮어쓰기 전 확인
-v이동 과정 출력
-n대상이 이미 있으면 덮어쓰지 않음
비하인드 스토리

같은 디스크(파일시스템) 안에서 mv는 실제로 파일 내용을 복사하지 않는다. 폴더 목차에 적힌 위치 정보만 바꿔치기하기 때문에 수십 기가바이트짜리 파일도 순식간에 "이동"된다. 하지만 외장하드처럼 다른 파티션으로 옮길 땐 내부적으로 복사 후 원본 삭제가 일어나 시간이 걸린다 — 같은 mv인데 속도 차이가 나는 이유다.

↑ 목차로

ls

list

파일·디렉토리
형식ls [옵션] [경로]
~ %ls -la
drwxr-xr-x 5 me staff 160 9 29 09:03 .
-rw-r--r-- 1 me staff 1204 9 28 22:11 report.txt
-rw------- 1 me staff 52 9 28 22:11 .env
주요 옵션
-l권한·크기·수정일 등 상세 정보
-a숨김 파일까지 표시
-h용량을 KB/MB 단위로 표시
-t수정 시간 순 정렬
-R하위 폴더까지 재귀적으로 표시
맨 앞자리 읽는 법

d = 디렉토리, - = 일반 파일, l = 심볼릭 링크. 그 뒤 9자리는 소유자·그룹·기타 사용자 순서의 rwx 권한이다.

비하인드 스토리

왜 숨김 파일은 마침표(.)로 시작할까? 초기 유닉스 개발자들이 ls 목록에서 현재 폴더(.)와 상위 폴더(..) 항목을 화면에 안 보이게 하려고, 이름이 마침표로 시작하는 항목은 건너뛰도록 임시로 짜둔 것이 시작이었다. 그런데 사람들이 이 허점을 이용해 설정 파일 이름 앞에 마침표를 붙여 "숨기기" 시작했고, 그것이 오늘날까지 이어진 숨김 파일 관례가 되었다 — 원래는 기능이 아니라 부작용이었다는 이야기다.

↑ 목차로
02

찾고 뒤지기

파일 자체를 찾을 땐 find, 파일 안의 내용을 찾을 땐 grep. 역할이 다르니 짝지어 외우면 편하다.

find

find

검색
형식find 검색경로 -조건 값
~ %find . -name "*.txt"
./notes/report.txt
./draft.txt
~ %find . -mtime -7
최근 7일 이내 수정된 파일만 표시
주요 옵션
-name이름으로 검색(대소문자 구분)
-iname대소문자 무시하고 검색
-type f/d파일(f) 또는 폴더(d)로 제한
-size +10M10MB 이상 파일
삭제와 조합

find . -name "*.log" -delete 처럼 삭제와 묶어 쓸 수 있다. 되돌릴 수 없으니 -delete를 빼고 먼저 실행해 어떤 파일이 걸리는지 확인한 뒤 붙이는 게 안전하다.

기억법

이름 그대로 find = 찾다. grep과 헷갈릴 땐 "find는 파일을, grep은 내용을 찾는다"로 구분한다.

↑ 목차로

grep

global regular expression print

검색
형식grep "검색어" 파일명
~ %grep -rni "todo" src/
src/App.tsx:42:// TODO: 강의 3장 슬라이드 추가
src/utils.ts:8:// todo: 정렬 함수 리팩토링
주요 옵션
-r하위 폴더까지 재귀 검색
-i대소문자 구분 안 함
-n줄 번호 표시
-v매칭되지 않는 줄만 출력
-l매칭된 파일명만 출력
유래

"global regular expression print"의 줄임말. 옛 텍스트 편집기 ed에서 쓰던 g/re/p (전역/정규식/출력) 명령 조합에서 이름이 나왔다.

비하인드 스토리

벨 연구소의 더그 매킬로이가 켄 톰슨에게 "ed 편집기의 전역 검색 기능만 따로 떼어 독립 프로그램으로 만들어 달라"고 부탁했고, 톰슨이 하룻밤 만에 만들어 다음 날 아침 내놓았다는 일화가 전해진다. "작은 일을 잘하는 작은 도구를 여러 개 만들어 조합한다"는 유닉스 철학을 가장 잘 보여주는 사례로 꼽힌다.

↑ 목차로
03

권한 관리

누가 읽고 쓰고 실행할 수 있는지를 정하는 명령어. 숫자만 이해하면 어렵지 않다.

chmod

change mode

권한
형식chmod 숫자|기호 파일명
~ %chmod +x deploy.sh
실행 권한 추가, 스크립트를 ./deploy.sh 로 실행 가능
~ %chmod 755 deploy.sh
소유자 rwx, 그룹·기타 r-x
권한 숫자표
7rwx (읽기+쓰기+실행)
6rw- (읽기+쓰기)
5r-x (읽기+실행)
4r-- (읽기만)
기호 방식
u/g/o/a소유자/그룹/기타/전체
+/-/=추가/제거/지정
-R폴더 하위 전체에 재귀 적용
기억법

r=4, w=2, x=1은 사실 2진수 자리값(100, 010, 001)과 같다. 원하는 권한을 더하면 그게 곧 숫자다: 읽기+실행만 원하면 4+1=5.

꿀팁

chmod 777(모두에게 모든 권한)은 편하지만 보안 위험이 크다. 꼭 필요한 최소 권한만 주는 습관을 들이자.

↑ 목차로
04

압축과 보관

여러 파일을 하나로 묶거나 다시 풀 때 쓰는 명령어.

tar

tape archive

압축
형식tar 옵션 파일명.tar.gz 대상
~ %tar -czvf backup.tar.gz src/
src 폴더를 backup.tar.gz 하나로 압축
~ %tar -xzvf backup.tar.gz
현재 위치에 압축 풀기
옵션 뜻
-ccreate, 새 압축 파일 생성
-xextract, 압축 풀기
-tlist, 내용물만 확인
-zgzip 압축/해제(.tar.gz일 때 필요)
-vverbose, 과정 출력
-ffile, 뒤에 파일명 지정(항상 마지막)
유래

tape + archive. 1970년대에 여러 파일을 자기 테이프(tape)에 순서대로 이어 기록해 보관(archive)하던 방식에서 이름이 그대로 남았다. 여러 파일이 하나로 뭉쳐진 결과물을 "타볼(tarball)"이라 부르는 것도 여기서 나온 은어다.

꿀팁

압축을 풀지 않고 안에 뭐가 들었는지만 보고 싶다면 tar -tzvf 파일명 을 쓰면 된다.

↑ 목차로
05

네트워크와 원격 접속

인터넷에서 데이터를 가져오거나, 다른 컴퓨터에 안전하게 접속하고 파일을 주고받는 명령어들.

curl

client URL

네트워크
형식curl [옵션] URL
~ %curl -O https://example.com/file.zip
원본 파일명 그대로 다운로드
~ %curl -I https://example.com
HTTP/2 200
content-type: text/html
주요 옵션
-O / -o원본 이름 저장 / 이름 지정 저장
-L리다이렉트 따라가기
-I헤더만 확인
-XHTTP 메소드 지정(POST 등)
-H / -d요청 헤더 / 본문 데이터
유래

"Client URL"의 줄임말. 1996년 스웨덴 개발자 다니엘 스텐베리가 만든 httpget이 urlget을 거쳐 curl로 이름을 바꿨다.

꿀팁

API 키 같은 민감정보를 -H나 -d에 직접 적으면 터미널 히스토리에 평문으로 남는다. 환경변수나 별도 설정 파일로 분리하는 편이 안전하다.

↑ 목차로

wget

web get

네트워크
형식wget URL
~ %wget https://example.com/file.zip
현재 위치에 file.zip으로 자동 저장
curl과 무엇이 다른가
wget다운로드 특화, 재귀 다운로드(-r) 지원, 이어받기 강함
curlAPI 호출 특화, 헤더·메소드 세밀 제어
유래

web + get. GNU 프로젝트로 1996년 등장했고, 원래 후보 이름은 "geturl"이었지만 상표 문제로 wget이 되었다. macOS엔 기본 내장돼 있지 않아 보통 brew install wget으로 따로 설치한다.

↑ 목차로

ssh

secure shell

네트워크
형식ssh 사용자명@호스트주소
~ %ssh user@example.com
비밀번호 또는 키 인증 후 원격 셸 접속
~ %ssh -i ~/.ssh/id_ed25519 user@example.com
지정한 키 파일로 접속
주요 옵션
-p포트 번호 지정(소문자)
-i개인키 파일 지정
-v연결 과정 상세 출력
자주 같이 쓰는 도구

scp(파일 복사), ssh-keygen(키 생성), ~/.ssh/config(자주 쓰는 서버 별칭 등록)

비하인드 스토리

1995년 핀란드 헬싱키공과대학의 타투 윌로넨은 자신이 속한 대학 네트워크에서 비밀번호를 가로채는 스니핑 공격을 직접 당했다. 당시 널리 쓰이던 rlogin과 telnet은 비밀번호를 암호화 없이 그대로 전송하고 있었기 때문. 이 경험이 계기가 되어 그는 암호화된 원격 접속 프로그램 ssh를 직접 만들었고, 오늘날까지 원격 접속의 표준이 되었다.

↑ 목차로

scp

secure copy

네트워크
형식scp 원본 대상
~ %scp file.txt user@example.com:~/backup/
로컬 → 원격 업로드
~ %scp -r src/ user@example.com:~/app/
폴더 전체 복사(재귀)
주요 옵션
-r폴더 복사 시 필요
-P포트 지정(대문자! ssh는 소문자 -p)
-i특정 SSH 키 사용
유래

secure copy. ssh 위에서 동작하며, 비밀번호를 암호화 없이 주고받던 예전의 rcp(remote copy)를 대체하기 위해 등장했다.

꿀팁

ssh는 소문자 -p, scp는 대문자 -P로 포트를 지정한다. 실무에서 가장 자주 헷갈리는 옵션 중 하나다.

↑ 목차로

rsync

remote sync

네트워크
형식rsync 옵션 원본 대상
~ %rsync -avP src/ backup/
sending incremental file list
App.tsx 12,048 100% 4.21MB/s 0:00:00
~ %rsync -avn src/ backup/
dry-run, 실제 복사 없이 무엇이 바뀔지만 미리 확인
주요 옵션
-aarchive, 속성 유지하며 재귀 복사
-P진행률 표시 + 이어서 전송
--delete원본에 없는 파일은 대상에서도 삭제
-ndry-run, 미리보기
cp/scp와 다른 점

파일 전체를 다시 보내지 않고 달라진 부분(delta)만 찾아 전송한다. 그래서 큰 폴더를 반복 동기화할 때 훨씬 빠르다.

비하인드 스토리

1996년 호주 개발자 앤드루 트리젤(삼바 SMB 서버 개발자로도 유명하다)은 박사 논문에서 "두 파일의 차이 나는 조각만 찾아 전송하는" 알고리즘을 제안했다. 이 알고리즘을 그대로 구현한 것이 rsync이며, 지금도 백업 도구 대부분이 이 방식을 빌려 쓰고 있다.

꿀팁

--delete는 대상 쪽 파일을 지울 수 있어 되돌릴 수 없다. 실행 전 -n(dry-run)으로 먼저 확인하는 습관을 들이자.

↑ 목차로
06

프로세스 관리

지금 실행 중인 프로그램을 확인하고, 필요하면 멈추는 명령어.

ps

process status

프로세스
형식ps [옵션]
~ %ps aux | grep node
me 12345 0.3 1.2 node server.js
주요 옵션
a다른 사용자의 프로세스도 표시
uCPU·메모리 등 상세 정보
x터미널에 종속 안 된 프로세스도 표시
핵심 컬럼

PID 프로세스 고유 번호(종료할 때 필요), %CPU·%MEM 사용률, COMMAND 실행 명령어

↑ 목차로

kill

신호(signal)를 보내는 명령

프로세스
형식kill [-신호번호] PID
~ %kill 12345
정상 종료 신호(SIGTERM) 전송, 프로세스가 정리 후 종료
~ %kill -9 12345
강제 종료(SIGKILL), 즉시 종료
알아야 할 신호
-15SIGTERM(기본), 정상 종료 요청
-9SIGKILL, 무조건 강제 종료
-1SIGHUP, 재시작·설정 재로드
이름으로 종료

killall node 이름이 node인 프로세스 전부 종료, pkill -f "server" 명령어에 server가 포함된 프로세스 종료

기억법

이름은 "죽이다"지만 사실은 "신호를 보낸다"가 더 정확하다. -9만 진짜로 무조건 죽이고, 나머지는 프로그램이 받아서 알아서 처리하도록 부탁하는 신호다.

비하인드 스토리

SIGHUP의 HUP은 "Hang Up", 옛 전화선을 끊는다는 뜻이다. 원래는 터미널과의 연결이 끊겼을 때 커널이 자동으로 보내던 신호였는데, 오늘날 많은 서버 프로그램들은 이 신호를 "설정 파일을 다시 읽어라"는 의미로 재활용해서 쓰고 있다. 전화를 끊는다는 옛 통신 용어가 지금도 서버 재시작 신호 이름에 살아남아 있는 셈이다.

↑ 목차로
07

비교와 용량 확인

텍스트가 얼마나 다른지, 디스크를 얼마나 쓰고 있는지 확인하는 명령어.

diff

difference

비교
형식diff 파일1 파일2
~ %diff -u a.txt b.txt
< 강의 3장 초안
---
> 강의 3장 수정본
출력 읽는 법

<는 왼쪽(a.txt)에만 있는 줄, >는 오른쪽(b.txt)에만 있는 줄을 뜻한다.

주요 옵션
-uunified 형식(git diff와 비슷한 표시)
-r폴더 전체 재귀 비교
-q다른지 여부만 간단히 표시
비하인드 스토리

1974년 벨 연구소의 더글러스 매킬로이가 만들었다. 두 텍스트에서 "최장 공통 부분열"을 찾는 알고리즘(훗날 헌트-매킬로이 알고리즘으로 불림)을 기반으로 하며, 오늘날 git diff와 patch 명령의 뿌리가 바로 이 프로그램이다.

꿀팁

git으로 관리되는 프로젝트라면 diff 대신 git diff를 쓰는 편이 색상 표시나 변경 이력 면에서 더 편리하다.

↑ 목차로

du

disk usage

용량
형식du -sh 폴더명
~ %du -sh *
1.2G node_modules
48M dist
3.1M src
주요 옵션
-ssummarize, 총합만 표시
-h사람이 읽기 쉬운 단위(K/M/G)
-a파일 단위까지 표시
df와 구분하기

du는 "이 폴더가 얼마나 썼는지", df는 "디스크 전체가 얼마나 남았는지" — 짝지어 외우면 헷갈리지 않는다.

꿀팁

du -sh * | sort -rh 로 용량 큰 항목부터 정렬해서 보면 무엇이 용량을 많이 차지하는지 바로 눈에 띈다.

↑ 목차로

df

disk free

용량
형식df -h
~ %df -h /
Filesystem Size Used Avail Use%
/dev/disk3s1 460G 210G 240G 47%
주요 컬럼
Size전체 용량
Used사용 중인 용량
Avail남은 용량
Use%사용률
du vs df

du -sh 폴더 → 특정 폴더 용량 확인. df -h → 디스크(파티션) 전체 여유공간 확인.

↑ 목차로
08

셸 환경 설정

터미널을 내 스타일대로 꾸미고, 변수와 설정을 다루는 명령어. 모두 zsh/bash 같은 셸 자체의 내장 기능이다.

alias

별명

셸 설정
형식alias 별칭='명령어'
~ %alias ll='ls -lah'
~ %ll
ls -lah가 실행된 것과 동일한 결과
확인·삭제·영구 적용
alias등록된 목록 전체 보기
unalias ll해당 별칭 삭제
~/.zshrc여기에 적어야 터미널을 새로 열어도 유지됨
유래

특별한 약자 없이 영단어 "별명(alias)"을 그대로 가져온 이름이다.

꿀팁

alias로 ls 같은 기존 명령어 이름을 덮어써도, \ls 처럼 백슬래시를 앞에 붙이면 원본 명령어를 그대로 쓸 수 있다.

↑ 목차로

export

환경변수 내보내기

셸 설정
형식export 변수명=값
~ %export NODE_ENV=production
~ %echo $NODE_ENV
production
export 유무 차이
MY_VAR=hello현재 셸에서만 쓰임
export MY_VAR=hello이 셸이 실행하는 다른 프로그램에도 전달됨
확인·삭제

env 전체 환경변수 목록, unset 변수명 삭제

꿀팁

API 키·비밀번호는 export로 셸 설정 파일에 평문으로 남기지 말고, .env 파일 + .gitignore 조합으로 분리 관리하는 것이 안전하다.

↑ 목차로

source

원본을 지금 셸에 적용

셸 설정
형식source 파일명
~ %source ~/.zshrc
터미널을 새로 열지 않고도 방금 수정한 설정을 즉시 반영
~ %. ~/.zshrc
마침표 하나로 축약 가능, source와 완전히 동일
왜 필요한가

~/.zshrc에 alias나 export를 추가해도 이미 열려 있는 터미널엔 자동 반영되지 않는다. source로 즉시 다시 읽게 만들어야 한다.

유래

스크립트 원본(source)을 새 프로세스로 실행하는 게 아니라, 지금 이 셸 안에서 직접 읽어 실행한다는 뜻에서 붙은 이름이다.

↑ 목차로
맥 터미널 명령어 사전 · zsh 기본 프롬프트(%) 기준으로 작성 · 예시의 파일·폴더명은 이해를 돕기 위한 가상의 예시다.
